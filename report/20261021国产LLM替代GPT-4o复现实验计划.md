# 国产 LLM 替代 GPT-4o 的复现实验计划

更新日期：2026-10-22  
适用项目：C²BM（Causally Reliable Concept Bottleneck Models）与 BC-LLM（Bayesian Concept Bottleneck Models with LLMs）

## 1. 实验目标

两份论文代码使用了 GPT-4o 系列模型：C²BM 的核心对照包含 GPT-4o，BC-LLM 的公开主实验主要使用 GPT-4o-mini、私有临床实验使用 GPT-4o。由于这些模型已进入弃用周期，且 OpenAI API 的充值和访问存在现实困难，本阶段计划接入国内可调用的千问或 DeepSeek API，完成以下目标：

1. 验证两个代码仓库中依赖 LLM 的完整流程能够运行。
2. 优先跑通 `C²BM + Asia + predicted graph + seed 1`。
3. 比较不同 LLM 对因果边定向、最终因果图和下游任务准确率的影响。
4. 在 C²BM 链路稳定后，再接入调用量更大的 BC-LLM。

本实验属于**替代模型复现**，用于验证论文方法在其他高质量 LLM 上是否仍然成立，不能直接表述为 GPT-4o 原实验的严格复现。正式汇报时应分别标记为：

- `C²BM-GPT-4o`：论文报告结果或未来实际调用结果；
- `C²BM-Qwen3.7-Flash`：千问低成本主实验；
- `C²BM-Qwen3.8-Flash/Max`：必要时进行的质量升级实验；
- `C²BM-DeepSeek-Flash`：DeepSeek 替代实验。

## 2. GPT-4o 当前维护状态

截至 2026-10-21，OpenAI 官方信息如下：

1. `chatgpt-4o-latest` 已于 2026-02-17 从 API 中移除。
2. GPT-4o 的 API 快照 `gpt-4o-2024-08-06` 和 `gpt-4o-2024-11-20` 已于 2026-10-14 被宣布弃用。
3. 上述 GPT-4o API 快照计划于 2027-01-14 下线。
4. OpenAI 官方为这些 GPT-4 系列快照给出的迁移目标是 `gpt-6-luna`。
5. 本地 C²BM 配置使用未固定快照的 `gpt-4o`；BC-LLM 同时写有 `gpt-4o`、`gpt-4o-mini` 和若干 2024 年快照，因此长期依赖这些名称存在不可用或行为变化风险。

结论：GPT-4o 当前不是“完全不能调用”，而是已经进入明确的弃用和下线周期。若之后能够获得 OpenAI API，应尽快完成一次 GPT-4o 历史对照并缓存全部响应；新建的长期实验链路应改为可配置的多供应商接口。

## 3. 候选替代模型

### 3.1 推荐顺序

考虑到 BC-LLM 的逐样本概念抽取调用量极大，正式执行不再让两个旗舰模型分别跑完整矩阵，而采用“少量高质量推理 + 大量低价抽取”的组合方案：

| 实验环节 | 首选模型 | 对照或升级模型 | 主要原因 |
|---|---|---|---|
| C²BM 因果图补全 | `qwen3.7-flash-2026-07-15` | `deepseek-flash` | 输出只需 A/B/C，Flash 模型足以先验证；两者均支持 OpenAI 兼容接口 |
| BC-LLM 候选概念生成、概念先验 | `qwen3.8-max-0902` 或 `qwen3.8-flash` | `deepseek-flash` 小样本对照 | 调用次数少，但对语义理解和概念质量较敏感 |
| BC-LLM 文本/图像概念抽取 | `qwen3.7-flash-2026-07-15` | `qwen3.8-flash` 抽样复核 | 这是调用量和费用的主要来源；Qwen3.7-Flash 支持图像和结构化输出 |
| 跨供应商稳健性检查 | `deepseek-flash` | — | C²BM 可全量运行；BC-LLM 只抽取 5%～10% 样本，不复制整个全量矩阵 |

BC-LLM 代码已区分 `llm_iter` 与 `llm_extraction`，因此可以让高质量模型负责概念提议和先验判断，让低价模型负责海量逐样本概念标注。所有结果必须记录两个角色各自使用的模型，不能笼统标记为单一模型结果。

低成本方案优先级如下：

1. `qwen3.7-flash-2026-07-15`：默认批量模型；
2. `qwen3.8-flash`：质量不足时的升级模型；
3. `qwen3.8-max-0902`：只用于调用量很少且质量关键的概念生成/先验步骤；
4. `deepseek-flash`：第二供应商对照，不进行完整 BC-LLM 双份全量调用。

### 3.2 千问

原高质量方案建议使用 `qwen3.8-max`：

- 支持 OpenAI 兼容的 Chat Completions 和 Responses API；
- 支持 JSON Object、部分模型支持严格 JSON Schema；
- 支持文本和图像输入，可覆盖 BC-LLM 的 CUB 路线；
- 当前上下文长度为 1M；
- 华北 2（北京）公开原价为输入 ¥12/百万 token、输出 ¥36/百万 token。

工程冒烟测试可使用 `qwen3.8-max` 别名。正式可重复实验应尽可能固定版本，例如官方仍可调用时使用 `qwen3.8-max-0902`，并记录 API 返回的实际模型名。

考虑到全量费用，实际批量执行改为首选 `qwen3.7-flash-2026-07-15`：

- 单次请求输入不超过 32K token 时，华北 2（北京）输入 ¥0.2/百万 token、输出 ¥0.8/百万 token；
- Batch File 输入 ¥0.1/百万 token、输出 ¥0.4/百万 token；
- 支持文本、图像和视频输入；
- 支持 JSON/结构化输出、上下文缓存和批量推理；
- C²BM 和 BC-LLM 当前单次 prompt 通常远小于 32K，可使用最低价格档。

`qwen3.8-flash` 作为中间质量档，参考价格为输入 ¥0.8/百万 token、输出 ¥2.7/百万 token。它适合抽样复核或在 Qwen3.7-Flash 格式/质量不达标时升级，但不作为默认全量模型。

## 4. 本地代码现状与改造难度

### 4.1 C²BM：改造难度低

相关文件：

- `src/causally-reliable-cbm/conf/llm/gpt.yaml`
- `src/causally-reliable-cbm/src/completion/llm/llm_client.py`
- `src/causally-reliable-cbm/src/completion/graph_completion.py`
- `src/causally-reliable-cbm/src/completion/context_generator.py`

当前限制：

1. `llm_client.py` 通过模型名中是否包含 `gpt` 判断是否调用 OpenAI。
2. OpenAI API Key 从 `env.py` 读取，容易误提交或写入日志。
3. 请求没有显式限制输出 token 数。
4. 因果边定向依赖模型严格返回 `<answer>A</answer>`、`B` 或 `C`。
5. 默认 `max_tries=1`，格式错误会直接导致实验失败。

实际任务很简单：GES 产生 CPDAG 后，只对未定向边调用 LLM。模型根据概念、概念描述和可选 RAG 上下文返回 A/B/C，代码据此完成边定向。因此千问或 DeepSeek 只要兼容普通 Chat Completions 即可接入。

计划改造：

1. 将客户端改为供应商无关的 OpenAI 兼容客户端。
2. 增加 `provider`、`model`、`base_url`、`api_key_env`、`thinking`、`max_tokens` 配置。
3. API Key 只从环境变量读取，不写入代码和配置文件。
4. 为 A/B/C 输出增加严格校验和有限次数重试。
5. 保存每次请求的 prompt、原始响应、解析答案、token 用量、模型名和时间。
6. 保持论文提示词内容不变，避免同时改变模型和 prompt 两个变量。

拟新增配置：

```text
src/causally-reliable-cbm/conf/llm/qwen.yaml
src/causally-reliable-cbm/conf/llm/deepseek.yaml
```

建议配置结构：

```yaml
provider: qwen
name: qwen3.7-flash-2026-07-15
base_url_env: QWEN_BASE_URL
api_key_env: DASHSCOPE_API_KEY
temperature: 0
thinking: false
max_tokens: 64
max_tries: 3
```

### 4.2 BC-LLM：改造难度中等

相关文件：

- `src/bc-llm/llm-api-main/lab_llm/constants.py`
- `src/bc-llm/llm-api-main/lab_llm/llm_api.py`
- `src/bc-llm/src/llm_response_types.py`
- `src/bc-llm/scripts/extract_llm_concepts.py`
- `src/bc-llm/scripts/train_bayesian.py`

当前限制：

1. 可用模型由枚举写死，只识别 GPT、Anthropic、Bedrock 等已有类型。
2. OpenAI 分支没有暴露自定义 `base_url`。
3. 概念提议和概念抽取依赖 LangChain `with_structured_output()` 与 Pydantic 模型。
4. CUB 实验还会向模型发送 base64 图像。
5. Bayesian 搜索和逐样本概念抽取的调用量明显大于 C²BM。

计划改造：

1. 扩展模型配置，加入 Qwen 和 DeepSeek provider。
2. 为 `ChatOpenAI` 设置供应商对应的 `base_url` 和环境变量 Key。
3. 显式选择 JSON Schema 或 JSON Object 模式，不依赖供应商默认行为。
4. 保证 LLM 缓存键包含 `provider + model + 参数`，防止不同模型共用缓存。
5. 先验证纯文本结构化输出，再验证单张图片，最后运行小样本 Bayesian 流程。

## 5. 实验设计原则

### 5.1 思考模式

正式主对照先关闭思考模式：

- 千问：`extra_body={"enable_thinking": false}`，或使用等价的 `reasoning_effort="none"`；
- DeepSeek：`extra_body={"thinking": {"type": "disabled"}}`。

原因：

1. 论文使用的 GPT-4o 不是显式推理模型。
2. C²BM 最终只需要 A/B/C，长思维链增加成本且可能降低格式稳定性。
3. DeepSeek 在思考模式下会忽略 `temperature`，与论文的 `temperature=0` 不完全可比。

思考模式可以作为后续单独消融：

- `Qwen3.8-Max non-thinking` 与 `Qwen3.8-Max thinking`；
- `DeepSeek-Flash non-thinking` 与 `DeepSeek-Flash high`。

### 5.2 公平比较

替代模型比较分为两种口径：

1. **端到端替代**：每个模型独立完成查询扩展、RAG 检索、边定向和训练，回答“整条流水线能否工作”。
2. **受控 LLM 比较**：固定同一个 GES CPDAG 和同一份 RAG 上下文，只替换负责边定向的 LLM，回答“模型本身对边定向的影响”。

必须保持不变的条件：

- 数据和训练/验证/测试划分；
- GES 输入和随机 seed；
- prompt；
- RAG 文档或冻结后的上下文；
- C²BM 超参数；
- 输出解析与图后处理逻辑。

### 5.3 基于原论文数值的评估方案

本节数值均直接整理自本地两篇论文 PDF。需要先澄清原始模型口径：

- BC-LLM 来源：`doc/16679_Bayesian_Concept_Bottlen.pdf`，主要核对 PDF 第 7、8、10、25 页。
- C²BM 来源：`doc/23581_Causally_Reliable_Concep.pdf`，主要核对 PDF 第 7、8、10、34～36 页。

- C²BM 的因果图定向实验报告了 GPT-4o、GPT-4o-mini 和 GPT-5；直接替代 GPT-4o 时，应以附录 Table 9 的 **GPT-4o + CoT** 行作为主要受控基准。
- BC-LLM 的 CUB、模拟 MIMIC 等主实验使用 **GPT-4o-mini**，只有不可公开的 ZSFG 临床实验使用受保护环境中的 GPT-4o。因此 BC-LLM 不能笼统地全部标记为“替代 GPT-4o”。
- 论文中只有图、没有表格精确数值的结果，不人工估读小数；先比较曲线、排序和置信区间，若要严格数值复现，再用固定工具数字化原图并保存过程。

#### 5.3.1 C²BM：先比较图，再比较训练结果

论文每条未定向边重复查询 **10 次**并取多数答案。附录 Table 9 固定 GES 产生的不完整图，只改变 LLM 和提示策略；其 GPT-4o + CoT 基准如下，误差为 3 次运行上的论文报告不确定度：

| 数据集 | GPT-4o CoT SHD | GPT-4o CoT 错误边数 |
|---|---:|---:|
| Asia | 0.25 ± 0.00 | 1.00 ± 0.00 |
| Sachs | 2.25 ± 0.06 | 8.50 ± 0.18 |
| Insurance | 7.54 ± 0.52 | 21.0 ± 1.4 |
| Alarm | 4.7 ± 1.3 | 10.0 ± 2.2 |
| Hailfinder | 10.83 ± 0.51 | 21.50 ± 0.90 |

论文主流水线的端到端参考来自 Table 8（GES 与 GES + LLM/RAG）和 Table 7（true/predicted graph 下游准确率）：

| 数据集 | GES SHD | GES + LLM/RAG SHD | LLM 后错误边数 | Predicted graph task acc. | True graph task acc. |
|---|---:|---:|---:|---:|---:|
| Asia | 0.65 | 0.25 | 1 | 71.4 ± 1.7 | 71.0 ± 2.3 |
| Sachs | 3.40 | 1.83 | 7 | 65.3 ± 1.1 | 65.0 ± 1.3 |
| Insurance | 6.43 | 6.33 | 18 | 66.4 ± 1.5 | 66.4 ± 1.8 |
| Alarm | 5.41 | 4.95 | 10 | 62.5 ± 1.4 | 62.1 ± 1.5 |
| Hailfinder | 11.00 | 11.00 | 22 | 74.1 ± 1.8 | 73.0 ± 1.6 |

其中 task accuracy 的不确定度由论文按 5 次运行报告。国产模型按以下顺序验收：

1. **受控边定向**：复用完全相同的 GES CPDAG、RAG 上下文和 CoT prompt；每条边调用 10 次；每个模型独立生成 3 次图，报告 SHD 和错误边数的均值及与论文一致的不确定度。
2. **Asia 首要门槛**：最终 SHD 应达到 0.25、错误边数应为 1；这是论文 GPT-4o、GPT-4o-mini、GPT-5 在 Asia 上共同达到且误差为 0 的结果。若未达到，只能记为“流程跑通”，不能记为“图结果匹配”。
3. **严格数值匹配**：国产模型 SHD、错误边数的均值落入 Table 9 的 GPT-4o + CoT 报告区间，且双方误差区间相交；Asia 因原文误差为 0，必须精确达到 0.25 和 1。
4. **方法结论匹配**：若没有逐项落入 GPT-4o 区间，至少要求 GES + 国产 LLM/RAG 相比原始 GES 不增加 SHD 和错误边数，并保持论文“LLM refinement 改善或不损害图质量”的结论；此时标记为“结论复现”，不能标记为“GPT-4o 数值复现”。
5. **下游匹配**：每张最终图固定后，用相同 seeds 1–5 训练；国产 predicted graph 的 task accuracy 区间应与上表论文 predicted-graph 区间相交，同时不得明显劣于本机 true-graph 对照。
6. **科学结论复核**：继续检查干预曲线、cMNIST 去偏和 CelebA 公平性。CelebA 的明确目标是 C²BM 干预后 CaCE `0.0 ± 0.0%`；干预曲线在论文中没有表格精确值，只检验曲线趋势和相对基线排序，不伪造精确阈值。

自定义 SHD 必须使用论文 Appendix F.1 的非对称权重实现，不能换成 NetworkX 等库的默认 SHD，否则数值不可直接比较。

#### 5.3.2 BC-LLM：比较置信区间和方法排序

BC-LLM 主文 Table 1 在 CUB 的 37 个鸟类家族任务上使用 GPT-4o-mini，数据按 50/50 划分；每个任务的概念数为 `K = min(10, max(4, 类别数))`。论文数值如下：

| 方法 | Accuracy | AUC | Brier | OOD entropy |
|---|---:|---:|---:|---:|
| BC-LLM | 0.680 (0.614, 0.747) | 0.874 (0.840, 0.907) | 0.428 (0.357, 0.500) | 0.865 (0.693, 1.036) |
| LLM+CBM | 0.640 (0.573, 0.707) | 0.810 (0.768, 0.853) | 0.452 (0.377, 0.528) | 0.663 (0.474, 0.852) |
| Boosting LLM+CBM | 0.538 (0.463, 0.614) | 0.722 (0.673, 0.772) | 0.577 (0.499, 0.654) | 0.842 (0.630, 1.054) |
| Human+CBM | 0.658 (0.591, 0.725) | 0.835 (0.791, 0.879) | 0.499 (0.414, 0.584) | 0.758 (0.558, 0.959) |
| ResNet | 0.664 (0.613, 0.716) | 0.853 (0.821, 0.885) | 0.457 (0.398, 0.516) | 0.914 (0.748, 1.079) |

论文附录 Table 2 已经提供了一次“更换 LLM”的参照。改用 Claude 3.5 Haiku 后：

| 方法 | Accuracy | AUC | Brier |
|---|---:|---:|---:|
| BC-LLM | 0.665 (0.593, 0.736) | 0.849 (0.811, 0.888) | 0.443 (0.367, 0.519) |
| LLM+CBM | 0.583 (0.517, 0.648) | 0.771 (0.722, 0.821) | 0.507 (0.434, 0.580) |
| Boosting LLM+CBM | 0.640 (0.568, 0.712) | 0.811 (0.769, 0.852) | 0.552 (0.455, 0.649) |

这说明论文对“LLM 可替代性”的判据不是概念文本或指标完全相同，而是数值仍处于相近置信区间，并且 BC-LLM 相对比较方法的整体排序基本保持。国产模型按以下规则验收：

1. **设置一致**：完整 CUB 验证必须使用 37 个家族任务、相同 50/50 划分、相同 K、BC-LLM 最多 `T=5` epochs 或 25 iterations；小样本实验只能叫冒烟测试。
2. **严格数值匹配**：国产 BC-LLM 的 Accuracy、AUC、Brier、OOD entropy 点估计分别落入 GPT-4o-mini 主结果的 95% CI，且双方 95% CI 相交。
3. **跨 LLM 稳健性匹配**：若未全部命中 GPT-4o-mini 区间，点估计至少应处于论文两个 LLM 已展示区间的并集包络：Accuracy `[0.593, 0.747]`、AUC `[0.811, 0.907]`、Brier `[0.357, 0.519]`；同时 BC-LLM 仍须在 Accuracy/AUC/Brier 上整体优于使用同一国产模型的 LLM+CBM、Boosting LLM+CBM，才认定“方法结论复现”。
4. **不得混用供应商比较**：评估 Qwen/DeepSeek 时，BC-LLM 和 LLM+CBM、Boosting LLM+CBM 必须使用同一个 `llm_iter`/`llm_extraction` 组合；不能只替换 BC-LLM，再与论文中使用 GPT-4o-mini 的比较方法直接排名。
5. **MIMIC 概念恢复**：按论文设置使用 `K=6`、`T=5`，训练样本数为 100、200、400、800，报告 AUC、Brier、concept precision、concept recall 及 95% CI。论文 Figure 3 只给曲线，没有可直接抄录的精确表值，因此主要复核“400 样本时接近 Human(Oracle)+CBM”“数据增多时 BC-LLM 与比较方法差距扩大”两项结论。
6. **概念匹配规则**：不得用字符串完全相等判断。按论文 Appendix E.1，以两个概念在样本上的 LLM 标注绝对 Pearson 相关系数大于 0.5 作为候选匹配，再人工确认；Precision/Recall 必须用论文给出的后验概念定义计算。
7. **私有数据限制**：ZSFG 实验的公开数值包括 BC-LLM AUC `0.64 (0.58, 0.70)`、临床相关性平均评分约 2.5，但数据不可获得，不纳入本阶段硬性验收。论文该图中 BC-LLM Brier 的上界印为 `0.62`，与点估计及其他方法量级不一致，疑似排版错误，也不作为阈值。

#### 5.3.3 最终结论分级

| 等级 | 判定 |
|---|---|
| A：论文数值匹配 | 受控设置一致，国产模型核心指标的论文式置信区间与原模型区间相交，并保持下游结果 |
| B：方法结论复现 | 个别数值未进入原模型区间，但不劣于无 LLM/比较方法，且论文的模型排序和主要结论保持 |
| C：工程跑通 | API、结构化输出、训练和日志完整，但图质量或科学指标未达到 A/B |
| 失败 | 输出无法稳定解析、图无效、实验设置不一致，或关键结论反转 |

正式报告必须分别写出“工程通过”“论文数值匹配”“方法结论复现”，不能用“跑通”代替“复现成功”。

成本计算：

```text
总成本 = 输入 token / 1,000,000 × 输入单价
       + 输出 token / 1,000,000 × 输出单价
```

控制措施：

1. C²BM 输出限制为 64 token 左右。
2. 主对照关闭思考模式。
3. 先图生成、后训练，先 seed 1、后五 seed。
4. 开启本地响应缓存，同一 prompt 不重复扣费。
5. 每个阶段设置预算上限，达到上限自动停止。
6. BC-LLM 先限制样本数、epoch 和 MCMC 轮数。
7. 支持时可考虑 Batch API，但必须把批处理结果与实时调用分开记录。
8. BC-LLM 使用双模型分工：`llm_iter` 使用高质量模型，`llm_extraction` 使用 Qwen3.7-Flash。
9. DeepSeek 只对 BC-LLM 做 5%～10% 抽样复核，不进行第二份完整全量运行。
10. 暂缓“370 个预定义概念 × 全部 CUB 图像”的高消耗基线，待主方法结果有效后再决定是否补跑。
11. 将概念判断的 reasoning 限制为简短理由，并根据每批概念数量设置合理的最大输出 token，避免无意义长输出。
