## 4. Hailfinder 并行异常与处理

- 最初将 Hailfinder seeds 2–5 放在同一 GPU 并行训练，虽然均正常退出，但 seeds 3/4 分别只有 62.20%/62.60%。
- 使用完全相同的 seed 3 缓存数据独占 GPU 重跑后得到 72.10%，相差 9.90 个百分点，说明该设置对同卡多进程的数值非确定性敏感。
- 正式统计使用五个无 GPU 竞争的串行结果：73.60%、74.50%、72.10%、71.85%、70.35%。没有挑选或删除预定 seed。
- 异常并行结果保留为 `metrics_parallel_diagnostic.csv` 和 `summary_parallel_diagnostic.csv`，但不进入论文复现汇总。

串行补跑目录：`runs/c2bm/hailfinder_true_graph_serial_5seeds_2026-10-02`。当前没有待完成的训练任务。

## 5. 尚未完成的论文主实验

### 5.1 需要 LLM API

1. C²BM predicted-graph 主流程：GES 得到 CPDAG 后，使用 GPT 与 RAG 完成边定向和图修正。
2. C²BM Table 2 的因果图可靠性，以及 LLM/RAG 消融实验。
3. BC-LLM Bayesian 主方法：LLM 概念提议、概念抽取、MCMC 概念集合搜索。

GPT-4o 不可自行部署。若无法充值，可把代码适配到可部署的开源模型，但这将是“替代模型实验”，不能与论文 GPT-4o 结果直接等同。

### 5.2 不需要 API，但规模较大

1. Sachs、Insurance、Alarm、Hailfinder 的全部基线：约 100 次训练；可补齐 Table 1 的其余贝叶斯网络列。
2. 图腐败敏感性实验：约 210 次训练；仓库没有直接给出完整运行配置，需要补写图翻转、加边、删边和渐进扁平化逻辑。
3. CelebA、CUB、Pneumothorax 等真实图像实验：需要较大的原始数据与特征提取成本，部分主流程仍依赖 predicted graph。

## 6. 建议后续顺序

1. 获得 GPT API 后，先复现 `Asia + predicted graph + seed 1`，验证完整图发现和训练链路。
2. 将 predicted-graph Asia 扩展到五随机种子，与当前 true-graph 结果直接比较。
3. 跑通 BC-LLM 的最小 Bayesian LLM 实验，再决定是否扩大数据集和 MCMC 轮数。
4. 根据研究重点选择：补全其余基线，或实现图腐败消融；不建议在主方法尚未跑通前一次性启动全部大规模实验。
